الشريحة 2

Git — ذاكرة مشروعك البرمجي

Git هو نظام موزّع للتحكم في إصدارات الملفات والمشاريع.

  • يتتبع التعديلات التي تطرأ على ملفات المشروع بمرور الوقت.
  • يتيح الرجوع إلى إصدارات سابقة عند الحاجة.
  • يمكّنك من تجربة أفكار جديدة دون التأثير في العمل الأساسي.
  • يعمل محليًا على جهازك، ولا يحتاج إلى GitHub لكي يعمل.

الشريحة 4

تعرّف على المصطلحات المهمة

  • Repository المستودع

    المكان الذي يحتوي على ملفات المشروع وسجل تغييراته.

  • Commit الحفظ المرحلي

    تسجيل مجموعة من التعديلات في سجل المشروع.

  • Branch الفرع

    مسار مستقل لتطوير ميزة أو تجربة تعديل.

  • Merge الدمج

    جمع التعديلات من فرع إلى فرع آخر.

  • Clone الاستنساخ

    إنشاء نسخة محلية من مستودع موجود.

  • Push الرفع

    إرسال التعديلات المحلية إلى المستودع البعيد.

  • Pull الجلب والدمج

    الحصول على التعديلات البعيدة ودمجها وفق سلوك الأمر المستخدم.

الشريحة 5

كيف تسجّل تغييراتك؟

  1. 1

    تعديل الملفات

    طبّق تغييراتك داخل المشروع.

  2. 2

    مراجعة التغييرات

    git status

  3. 3

    تجهيز الملفات

    git add

  4. 4

    تسجيل التغييرات

    git commit

  5. 5

    رفع التغييرات

مثال عملي

terminal
git status
git add .
git commit -m "Add homepage"
git push

لاحظ أن git add . يجهّز التغييرات الموجودة ضمن النطاق الحالي، ولذلك يُفضَّل مراجعة الملفات قبل تسجيلها.

الشريحة 6

أوامرك الأولى مع Git

إنشاء المشروع

  • git init إنشاء مستودع Git جديد في المجلد الحالي.
  • git clone <repository-url> جلب نسخة كاملة من مستودع موجود.

حفظ التغييرات

  • git status يوميًا عرض حالة الملفات والتغييرات.
  • git add <file> يوميًا تجهيز ملف أو أكثر للتسجيل.
  • git commit -m "Your message" يوميًا تسجيل التغييرات المجهزة برسالة وصفية.
  • git log استعراض سجل الإصدارات السابقة.

إدارة الفروع

  • git branch عرض الفروع الموجودة في المشروع.
  • git switch <branch-name> الانتقال إلى فرع محدد.

المزامنة

  • git pull يوميًا جلب التعديلات البعيدة ودمجها محليًا.
  • git push يوميًا رفع تعديلاتك إلى المستودع البعيد.

الأوامر المعلَّمة بـ يوميًا هي ما سيستخدمه المبتدئ في معظم أيامه.

الشريحة 7

اعمل على ميزات جديدة بأمان

  • لماذا الفروع؟

    الفرع مسار مستقل يتيح العمل على ميزة جديدة دون تعديل الفرع الأساسي main مباشرة.

  • ما هو Pull Request؟

    في GitHub، طلب لمراجعة التغييرات ومناقشتها مع الفريق قبل دمجها.

  • العلاقة بين المفاهيم

    تُسجَّل التعديلات Commit على Branch، ثم تُراجَع عبر Pull Request، وأخيرًا تُدمَج في Merge.

الشريحة 8

من جهازك إلى الإنترنت

  1. 1 تسجيل الدخول إلى GitHub.
  2. 2 إنشاء مستودع جديد من زر «New Repository».
  3. 3 اختيار اسم المستودع وتحديد مستوى ظهوره (عام أو خاص).
  4. 4 إنشاء المستودع.
  5. 5 ربط المشروع المحلي بالمستودع البعيد — إذا كان المشروع موجودًا محليًا.
  6. 6 رفع الملفات إلى المستودع.
  7. 7 التحقق من ظهور الملفات على الموقع.
terminal
git remote add origin <repository-url>
git branch -M main
git push -u origin main

هذه الأوامر تفترض أن المشروع المحلي مهيّأ بالفعل باستخدام Git، ويجب استبدال <repository-url> برابط المستودع الحقيقي.

الشريحة 9

لننفّذ مشروعًا صغيرًا

1 تهيئة المشروع

terminal
mkdir my-project
cd my-project
git init

أنشأنا مجلدًا جديدًا وحوّلناه إلى مستودع Git يتتبع تغييراته.

2 الحفظ المرحلي

terminal
git status
git add index.html
git commit -m "Initial commit"

أنشأنا ملف index.html مسبقًا، ثم سجّلنا أول إصدار من المشروع.

3 الرفع إلى GitHub

terminal
git remote add origin <repository-url>
git branch -M main
git push -u origin main

اربطنا مستودعنا المحلي بمستودع جديد على GitHub ورفعنا المشروع إليه.

تنبيه: استبدل <repository-url> بعنوان المستودع الفعلي، ولاحظ أن اسم الملف في المثال يفترض أن index.html قد أُنشئ مسبقًا.

الشريحة 10

أصبحت مستعدًا للانطلاق

أهم ما تعلمناه

  • Git يتتبع تاريخ التغييرات.
  • GitHub يساعد على استضافة المشاريع والتعاون عليها.
  • Commit يسجّل التعديلات.
  • Branch يتيح تطوير الميزات بصورة مستقلة.
  • Push يرفع التغييرات، وPull يجلب التعديلات البعيدة ويدمجها وفق سلوك الأمر المستخدم.
  • Pull Request يسهّل مراجعة التعديلات قبل دمجها.

ماذا بعد؟

  • إنشاء أول مستودع شخصي.
  • رفع مشروع بسيط.
  • تجربة الفروع وطلبات الدمج.
  • استكشاف المشاريع مفتوحة المصدر.
